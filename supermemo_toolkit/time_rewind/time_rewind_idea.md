- 命令名：time
- 只能冷备份（.kno 是个 950 字节的独占锁元数据头，激活期间只做字段级批处理更新，锁定时外部读不到，解锁时做最终提交。热备份在文件层面不可行，冷备份是唯一正确选择。）
	- 集合激活状态监测（轮询的方式，.kno（核心锁）文件锁/事件监测）
		- 多集合激活状态同时检测并应用备份程序。
		- systems可以做一个整个的git，忽略子目录git文件。然后可以作为上传备份提交，一般不必要
		- 裸仓库备份行不通，必须用常规仓库，备份和恢复的时候，就用py自动处理kno文件。必须保证kno文件在工作区和实际位置的一致性
		- 根据激活状态去执行切换动作
			- 剩下就是动作。
				- 打开集合
				- 如果激活时间少于1分钟直接重置集合。
				- 备份集合
				- 压缩动作
				- 每次执行动作之前检查是否要压缩
			- 使用git裸仓库分集合分别备份。
				- 裸仓库 = 只有版本数据，没有工作区的仓库。用不同的裸仓库存储不同集合的版本历史，通过 --git-dir + --work-tree 让 Git 直接操作统一的工作区，恢复时只覆盖指定集合的文件。可以从裸仓库中把指定文件提取到指定路径。
				- 每个集合按时间线备份，时间间隔自定义
				- 压缩策略（冷热分离）近期备份保持为 Git 普通 commit（热，可快速 diff/恢复）。
				- 压缩可以延后，这样前面是热更新，后面的冷备份。
				- 分层压缩策略——从分钟级备份逐步聚合成天、月、季
				- 第一区段：每天内可以备份m个n分钟，用于撤销和重做，下一天天进行压缩为一天
					- 这样一天内时间线可以恢复
				- 第二区段：每月内有一月天，下一个月将这些天进行压缩为一个月
					- 一个月内的每天时间线可以恢复
				- 第三区段：每个季节内有三个月，下个季节将这些月压缩为一个季节，比如夏季
				- mn个分钟备份、30个天备份、3个月备份、4x年个年备份。
