- 两个状态
	- 主程序运行状态监测（在sm软件生命期间进行备份）
		- 启动器模式
		- 让 Python 脚本成为你启动 SuperMemo 的唯一入口，完美接管程序的生命周期。
		- 实现方式：Python 脚本通过 subprocess.Popen() 启动 sm18.exe，然后循环监听该进程状态。一旦监测到主进程退出，subprocess 的进程句柄就会收到通知。
		- 开始监测集合激活状态。
	- 集合激活状态监测（轮询的方式，.kno（核心锁）文件锁/事件监测）
		- 打开软件只是激活一个集合并开始当前集合都生命周期。所以打开软件只是激活第一个集合，关闭软件只是结束最后一个集合
		- Maths/stats/time.dat, 可以用这个文件修改时间作为激活开始的标志。打开集合就会更新到最新时间。只有打开动作会更新修改时间。
			- Maths/stats/time.tim，这个是上一次
			- Maths/stats/time.~ti，这个是上上一次。
		- 根据激活状态去执行切换动作
			- 剩下就是动作。
				- 打开集合
				- 如果激活时间少于1分钟直接重置集合。
				- 备份集合
				- 压缩动作
				- 每次执行动作之前检查是否要压缩
			- 使用git裸仓库分集合分别备份。
				- 裸仓库 = 只有版本数据，没有工作区的仓库。用不同的裸仓库存储不同集合的版本历史，通过 --git-dir + --work-tree 让 Git 直接操作统一的工作区，恢复时只覆盖指定集合的文件。
				- 每个集合按时间线备份，时间间隔自定义
				- 压缩策略（冷热分离）近期备份保持为 Git 普通 commit（热，可快速 diff/恢复）。
				- 压缩可以延后，这样前面是热更新，后面的冷备份。
				- 分层压缩策略——从分钟级备份逐步聚合成天、月、季
				- 第一区段：每天内可以备份m个n分钟，下一天天进行压缩为一天
					- 这样一天内时间线可以恢复
				- 第二区段：每月内有一月天，下一个月将这些天进行压缩为一个月
					- 一个月内的每天时间线可以恢复
				- 第三区段：每个季节内有三个月，下个季节将这些月压缩为一个季节，比如夏季
				- mn个分钟备份、30个天备份、3个月备份、4x年个年备份。
